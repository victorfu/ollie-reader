## 1. 定位

「大耳狗的雲朵小窩」是一款單場景的溫柔養成遊戲:大耳狗喜拿(Cinnamoroll)住在雲朵造型的小窩裡,玩家是她唯一的主人。餵食、洗澡、摸摸、哄睡、佈置房間、換裝打扮,看著她越來越黏你。

與既有遊戲的分工:

- **不收集、不戰鬥、不會失敗** — 收集冒險是 Wonder Academy 的路線,塔防是甜心防衛隊的路線;這款只做「疼愛唯一一隻」的日常陪伴,像電子雞/任天狗。
- **是扭蛋代幣的消費出口** — 進階點心、玩具、家具、服裝都用「單字大冒險」賺的扭蛋代幣購買,讓練英文的動機從「想抽扭蛋」擴大為「想寵愛大耳狗」。

一句話:

> 打開遊戲,大耳狗跑過來說 "Good morning!";餵她吃草莓鬆餅、搓泡泡洗香香、摸摸頭,親密度升級解鎖她的新動作和新的英文短句;想買雲朵蛋糕但代幣不夠 → 去單字大冒險練幾題 → 回來寵愛她。

## 2. 設計目標

- 一次遊玩 5-10 分鐘,天天想回訪,回訪理由全部是正向的(心願、想念擁抱),沒有罪惡感。
- 「溫柔模式」:狀態有底線、永不生病難過;親密度只升不降。
- 輕度英文融入:大耳狗說簡短英文(TTS 發音+中文小字幕)、商品雙語呈現;**沒有考試、擋關、答題**。
- 融入既有代幣經濟,成為最大的代幣消費出口,間接驅動單字練習。
- 延續專案調性:溫暖、不暴力、手繪可愛風、私人使用。

## 3. 非目標

- 不做多隻寵物、不做繁殖/進化、不做寵物小遊戲廳(街機類遊戲 hub 裡已經有)。
- 不做推播通知、不做真實時間懲罰(生病、死亡、離家出走一概不存在)。
- 不新增後端服務與 Cloud Functions;沿用 Firebase Auth + Firestore + 既有交易模式。
- 不提供「重置寵物」入口(私人 App,必要時手動清文件;重置一段感情在情感上不合理)。
- v1 不做戶外場景(花園/散步)、拍照模式、節慶活動 — 列為未來擴充。

## 4. 核心循環

```text
打開遊戲(依真實時間呈現早/午/晚氛圍)
  -> 大耳狗跑過來問候(TTS:"Good morning!" 等)
  -> 查看三條狀態 + 今日心願泡泡
  -> 照顧互動:餵食 / 洗澡 / 摸摸 / 玩玩具 / 哄睡
  -> 獲得親密度 -> 升級 -> 解鎖新動作 / 新英文短句 / 專屬禮物
  -> 商店購物(進階點心、玩具、服裝、家具)
       -> 代幣不足 -> 「要不要去單字大冒險賺代幣?」 -> 練英文 -> 回來買
  -> 佈置房間 / 換裝
  -> 晚上哄睡("Good night! Sweet dreams…")
```

## 5. 玩法系統

### 5.1 狀態系統(溫柔模式)

三條會變化的狀態 + 一條只升不降的親密度。所有衰減都有**底線**,永遠不會更糟:

| 狀態 | 範圍 | 衰減 | 底線表現 |
|------|------|------|----------|
| 🍽️ 飽足 | 20–100 | 每 24 小時 -80(滿 → 底線) | 「肚子咕嚕咕嚕」,不會餓壞 |
| 🛁 清潔 | 30–100 | 每 72 小時 -70 | 「毛毛有點蓬蓬的」,不會生病 |
| 💗 心情 | 60–100 | 每 12 小時回落到 60(平靜) | 平靜,永遠不會難過 |
| ⭐ 親密度 | 0–∞ | **只增不減** | — |

規則:

- 衰減以「上次快照值 + 時間差」純函式推導,不跑背景任務(見 §8.4)。
- 飽足 ≥ 90 時拒吃:她說 "I'm full!"(可愛動畫,不是懲罰)。
- 清潔 ≥ 90 時洗澡仍可玩泡泡,但不再加親密度(防刷)。
- **想念機制**:距上次來訪 ≥ 48 小時,進場改播「衝過來抱住你」動畫 + "I missed you!",並加親密度 +10 — 久沒玩回來是獎勵,不是愧疚。
- **每日親密度上限 40**:所有加點來源(含想念、心願)都計入;到達後互動照樣有動畫與愛心,但顯示「她今天已經好幸福了 💕」。這是唯一的防刷機制,用正向語言呈現。

### 5.2 照顧互動

每個互動 = 動畫 + 音效 + 英文短句(TTS)+ 狀態變化:

| 互動 | 觸發 | 效果 | 英文短句範例 |
|------|------|------|--------------|
| 餵食 | 點心櫃選食物 | 飽足 +30(免費糧)/+45(進階);親密度 +3/+6;進階點心另 +10 心情 | "Yummy!" "I love it!" |
| 洗澡 | 點浴盆 → 手指搓泡泡 → 沖水 | 清潔 → 100;親密度 +6(清潔 < 90 時);甩毛+噴嚏蓬毛動畫 | "Bubbles!" |
| 摸摸 | 手指在她身上輕撫 | 心情 +5/次;親密度 +2;摸耳朵 → 耳朵擺動、摸肚子 → 打滾 | 咯咯笑聲 |
| 玩玩具 | 點玩具箱中已擁有的玩具 | 心情 +15;親密度 +2;每個玩具有專屬動畫 | "Let's play!" |
| 哄睡 | 19:00–07:00 點床鋪,每日一次 | 親密度 +4;燈光轉暗、蓋被、播搖籃曲氛圍 | "Good night! Sweet dreams…" |

睡眠細則:哄睡後她睡到 07:00 自動醒;睡著時來訪可「輕輕叫醒」,她揉揉眼睛開心醒來,**沒有起床氣**。白天偶爾看到她自己打盹(純氛圍)。

### 5.3 親密度等級與解鎖

等級稱號:L1 剛認識的朋友 → L5 好朋友 → L10 麻吉好朋友 → L15 最好的朋友 → L20 最重要的家人。

累積親密度門檻(L2 起):20, 50, 90, 140, 200, 270, 350, 440, 540, 650, 770, 900, 1040, 1190, 1350, 1520, 1700, 1890, 2090。以每日 30–40 點估算,約兩個月到滿級。

解鎖表(內容可與女兒討論微調;🎁 禮物是商店買不到的專屬物品,於 Phase 2 隨佈置/換裝系統生效,若屆時等級已超過則補發):

|------|------|------|------|
| L2 | 短句 "I love it!" | L11 | 🎁 星星掛飾(壁飾) |

| L5 | 🎁 一朵小花(桌飾) | L14 | 🎁 彩虹掛畫(壁飾) |

升級瞬間:愛心爆發動畫 + 新解鎖預覽卡(雙語)。已解鎖動作她會在待機時隨機表演,也可從「動作面板」點播。

### 5.4 每日心願

- 每天一個心願泡泡,以「日期 + uid」做種子決定,當日固定(換分頁/重整不會重抽)。
- 心願池與權重:**70% 免費可達成**(想被摸摸頭×5、想洗泡泡澡、想喝牛奶、想玩某個已擁有的玩具、想聽你說晚安),**30% 進階點心**(想吃隨機一種進階點心 — 這是輕輕把她推向單字練習的時刻)。
- 沒有任何已擁有玩具時,玩具類心願自動 fallback 成摸摸類。
- 達成:對應行動當日發生即自動偵測 → 愛心大爆發 + 親密度 +10。
- 未達成**零懲罰**:她不會失望,明天換新心願。

### 5.6 佈置模式(Phase 2)

- 進入佈置模式:家具在**地板區 / 牆面區**內自由拖放(無格線、允許重疊,大手把好拖),壁紙/地板一鍵更換。
- 大耳狗對新家具有反應:聞一聞、跳上沙發坐、鑽進被窩 — 佈置不是靜態貼圖,是她生活的地方。
- 版面存進雲端存檔(見 §8.2 `room`)。

### 5.7 換裝(Phase 2)

- 衣櫥面板:頭飾、頸飾兩槽,即穿即看;她穿新衣會開心轉一圈。
- 配件以 SVG 錨點(頭部/頸部群組)掛載,跟隨所有姿勢動作(見 §8.6)。

### 5.8 英文融入(輕度)

- 大耳狗所有台詞 = **簡短英文 + 中文小字幕**,以 SpeechContext TTS 發音(近期已修正裸英文詞用單語音色)。
- 短句庫隨親密度成長(§5.3),「她會說的話越來越多」本身就是英文學習內容。
- 問候依時段:Good morning! / Good afternoon! / Good evening! / (睡著時輕聲) Shh… I'm sleepy…
- 情境短句:見 §5.2 表格。全部收錄於 `data/phrases.ts`,zh/en 對照。
- **不出現任何題目、測驗、答錯**。

### 8.2 存檔 Schema(Firestore `gameProgress/{uid}/littleGames/cloudCottage`)

```ts
type PetSaveV1 = {
  schemaVersion: 1;
  stats: { fullness: number; clean: number; mood: number; statsAt: number };
  bond: { total: number; earnedToday: number; earnedDate: string }; // 本地日期 YYYY-MM-DD
  lastVisitAt: number;          // 想念判定(≥48h)
  lastSleepDate: string;        // 哄睡每日一次
  freeFood: { milk: number; cookie: number; restockDate: string };
  inventory: {
    snacks: Partial<Record<SnackId, number>>;   // 消耗品數量
    toys: ToyId[]; outfits: OutfitId[]; furniture: FurnitureId[];
    wallpapers: WallpaperId[]; floors: FloorId[];
  };
  equipped: { head?: OutfitId; neck?: OutfitId };
  room: {
    wallpaperId: WallpaperId; floorId: FloorId;
    placed: Array<{ id: FurnitureId; x: number; y: number; zone: "floor" | "wall" }>;
  };
  wish: { date: string; wishId: string; fulfilled: boolean };
  createdAt / updatedAt: serverTimestamp;
};
```

- 讀取時 `normalizePetSave` 鋪預設值再蓋存檔值(同 `normalizeGachaSave` / `fetchProgress` 的 backfill 慣例),缺欄位不炸。
- 本地快取:沿用 `gachaStorage` 的 cache key + 版本比較 + `storage` 事件跨分頁同步模式。
- 日期一律 `economyService.todayLocal()`(本地時區,避免跨日誤差);時鐘倒轉時 `restockDate` 在未來 → 不補貨也不清空,衰減用 `max(0, now - statsAt)`。

### 8.3 代幣交易(關鍵正確性)

- **購買**:仿 `recordGachaAttempt` — 單筆 `runTransaction` 同時讀 `gameProgress/{uid}`(餘額)與寵物文件,餘額不足丟 `CottageInsufficientCoinsError`,足夠則 `coins: 餘額-價格` + 物品入庫一起提交。**付了款一定有東西,沒付款一定沒東西**;多分頁不會重複扣款。
- **照顧行動**(餵食/摸摸/洗澡/哄睡,不涉及代幣):樂觀更新本地 state,非同步 `set(…, { merge: true })` 寫雲端;失敗以既有 Toast 提示並於下次互動重試。單一使用者、last-write-wins 已足夠。
- 本遊戲**不發代幣**(不與單字大冒險的賺幣定位競爭);心願獎勵只給親密度。

### 8.4 時間推導(不跑背景任務)

```
現在飽足 = clamp(快照值 - 衰減速率 × (now - statsAt), 底線, 100)
```

全部純函式(vitest 好測);畫面開著時每 60 秒 tick 重算一次顯示。時段由本地時刻推導(05–11 早晨、11–17 白天、17–21 傍晚、21–05 夜晚),驅動背景光線與問候語;哄睡窗口(19:00–07:00)是獨立規則。

### 8.5 TTS 與音效

- 台詞經 `SpeechContext.speakAsync(englishText)`;短句都很短(1–4 詞),失敗時靜默降級(字幕仍顯示,不打斷遊玩)。
- SFX(吃飯咀嚼、泡泡、愛心、搖籃曲氛圍)用輕量 WebAudio(仿 sweetheart `audio.ts`),可關閉。

### 8.6 美術與動畫

- 角色 = 手繪風 **SVG React 元件**(前例:MeteorGlider 的 canvas 手繪大耳狗、mushroom 的 Cinnamoroll 風主角;本作互動是 DOM/UI 型,SVG + Framer Motion 比 canvas 合適:配件錨點、拖放佈置、無障礙都更容易)。
- v1 姿勢:待機呼吸、小跑步、吃、開心(愛心)、洗澡、睡覺、擁抱;解鎖動作:轉圈、跳舞、打滾、耳朵飛行、雲朵彈跳。
- 配件掛在 SVG 頭/頸群組錨點上,跟隨姿勢變換。
- 色調:粉藍 × 奶油白雲朵系,依時段套光線濾鏡。

## 9. 錯誤處理

| 情境 | 行為 |
|------|------|
| 載入雲端失敗但有本地快取 | 用快取進場 + 頂部小橫幅「離線中,稍後自動同步」;購買停用 |
| 載入失敗且無快取 | 友善錯誤畫面 + 重試按鈕(不顯示技術訊息) |
| 購買時餘額不足 | 遊戲內對話框(§5.5),不是錯誤 Toast |
| 購買交易失敗(網路) | Toast「雲朵打了個噴嚏,再試一次」+ 可重試;因交易原子性,不會扣了款沒東西 |
| 照顧行動雲端寫入失敗 | 本地狀態保留 + Toast 輕提示,下次互動自動重試 |
| TTS 不可用 | 靜默降級,字幕照常 |
| 未登入進入 `/games/cottage` | 沿用其他遊戲的登入導引行為 |
