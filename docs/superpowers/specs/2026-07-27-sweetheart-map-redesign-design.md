# 甜心防衛隊 — 地圖與戰鬥改版

日期：2026-07-27
狀態：§1 已確認；§2–§4 為設計提案，實作中可調整

## 問題

玩家（小朋友）反應六件事，對應到程式碼的具體成因：

| 問題 | 成因 |
|------|------|
| 太單調 | 12 張地圖共用一套畫法：米色地板 + 格線 + 一條棕色折線，只有 `theme` 換色。地板上沒有任何東西，每張圖的玩法規則也完全相同。 |
| 太短 | 店門小徑路徑僅 2570px，最快的棉花糖飛賊 109px/s，24 秒就走到櫃檯。 |
| UI 很醜 | HUD 是一條白底藥丸列；畫布 letterbox 後左右留大片空白。 |
| 塔位很怪 | `levels.test.ts` 只驗「不壓路」「不出畫面」，沒有任何規則要求塔位打得到路。`{x:40,y:30}`（左上角）這種空砲位可以通過測試。 |
| 沒得玩 | 波次進行中玩家沒有任何可下的指令，只有 placeTower / upgrade / sell / startWave。 |

第六點「參考市面上的塔防」的結論散在下面各節：折返路線讓一座塔能對同一隻怪開多次火（Kingdom Rush、Bloons TD 6）、每隻角色自己的充能大招（植物大戰殭屍的植物食糧、明日方舟的技能）、地形區給每張圖玩法個性（Bloons TD 6 的水域與視線）。刻意不抄的是多層升級樹與拉仇恨——對小朋友太複雜。

## 決策前提

- **交付方式**：垂直切片。先用全新系統把地圖 1「店門小徑」做到好玩，確認手感後再套用其餘 11 關。
- **目標玩家**：小朋友為主。畫面要熱鬧、回饋要大、操作要少、讀字要少、失敗不懲罰。
- **絕招形式**：每隻角色自己的大招（類似植物大戰殭屍的植物食糧），不是全域技能鈕。
- **「太短」**指路太短，不是波數太少，也不是整體內容太少。
- **「太單調」**兩者皆是：看起來一樣，玩起來也一樣。
- **地圖做法**：保留折線路徑（引擎不動），塔位改成貼路生成，另加場景層。

## §1 塔位與路徑（已確認）

### 塔位從路徑生成

新增 `data/slotPlanner.ts`，純函式、不碰 DOM：

```ts
planSlots(paths: Vec2[][], plan: { count: number }): { id, x, y }[]
```

1. 沿路徑等弧長取樣，在取樣點的法線方向往左右各推 `SLOT_OFFSET`（88px = 路面半寬 30 + 塔位半徑 28 + 30 留白）產生候選點。
2. 淘汰：出畫面（含 `EDGE_MARGIN`）、離任一條路 < 58px、離已採用塔位 < `MIN_SLOT_SPACING` 110px、落在 solid prop 上。
3. 左右交替挑選，湊滿 `count`；候選不足時縮小取樣間隔重試。
4. id 由採用順序決定（`s1`、`s2`…），同樣的輸入永遠得到同樣的輸出。

`LevelSpec.slots` 換成 `slotPlan: { count: number }`。`compileLevel` 解析出實際座標，放進 `CompiledLevel.slots` 與 `slotById`；simulation 拿到的形狀不變，引擎邏輯一行不用改。renderer 與 BattleScreen 改讀 compiled 的 slots，TitleScreen 顯示 `slotPlan.count`。

### 新的測試不變式

取代原本兩條寬鬆的規則：

- **打得到路**：每個塔位 `distanceToPath(slot) <= 125`（藤蔓＝最短射程），下限維持 `> 58`。
- **有事做**：以速射射程 156 計算「射程內涵蓋的路徑長度」，每張圖的中位數 ≥ 400px、最小值 ≥ 180px。只擦到一個路口的角落塔位會被擋下來。

### 路徑加長並改成折返型

- 長度從 2570px 拉到約 4000px：棉花糖飛賊 24s → 37s，軟糖小兵 46s → 71s。
- 折返段之間留 200–260px，一個塔位放在兩段中間就能打到來回兩趟。同一座塔對同一隻怪開三次火，玩家才看得到「擋下來了」的過程。這條由上面的涵蓋率測試把關。

## §2 場景層

`LevelSpec` 新增兩個陣列，都不影響既有欄位：

```ts
props: { kind: PropKind; x: number; y: number; scale?: number; flip?: boolean }[]
zones: { kind: ZoneKind; x: number; y: number; radius: number }[]
```

**props** 純裝飾，畫在地板之上、路徑之下。店門小徑用：`shopFront`、`awning`、`bench`、`planter`、`sakura`、`lamp`、`cakeStand`、`balloon`。少數幾種帶輕微動畫（氣球上下浮、櫻花飄落），動畫只吃 `state.timeMs`，不進模擬狀態。

**zones** 是規則區域，每張圖挑 1–2 種，這就是各關的玩法個性：

- `sugarPool` 糖霜池：塔位落在圈內時射程 ×1.2。放塔前就看得到圈，讓塔位選擇有優劣。
- `ovenVent` 烤箱口：每 6 秒對圈內路面上的敵人造成一次固定傷害，附帶火焰特效。

`sugarPool` 在 `getTowerStats` 之後套用（compileLevel 時算出「哪些塔位在圈內」，模擬只查表）。`ovenVent` 需要模擬狀態：`BattleState` 增加 `zoneTimers: number[]`，`stepSimulation` 每步遞減，歸零時結算範圍傷害並丟一個 `splash` 特效。

## §3 絕招

### 充能

`LiveTower` 增加 `charge: number`（0–1）。每步累加：

```
charge += dtMs / CHARGE_TIME_MS + damageDealt / CHARGE_DAMAGE
```

時間項讓不造成傷害的應援塔也能充能；傷害項讓認真在打的塔充得更快。

充能以**角色**為單位彙總：同一個角色放了三座塔，三座的充能加總在一起，滿了之後三座**同時**放大招。放越多越快、也越猛——對小朋友來說這是看得懂的獎勵。

### 8 種大招（依主元素決定的打法分類）

| 打法 | 絕招 | 效果 |
|------|------|------|
| 速射 rapid | 彈幕 | 3 秒內攻速 ×4 |
| 糖漿 syrup | 糖漿大浪 | 射程 ×2 範圍內敵人減速 50%，持續 4 秒 |
| 藤蔓 vine | 藤蔓爆發 | 射程內持續傷害 5 秒 |
| 狙擊 sniper | 必中一擊 | 對場上血量最高的敵人造成 8 倍傷害 |
| 催眠 lullaby | 全體睡著 | 射程內敵人暈眩 2.5 秒 |
| 爆裂 burst | 煙火 | 射程內連續 5 次爆炸 |
| 重砲 cannon | 碎裂砲 | 射程內全體高傷 + 破甲 |
| 應援 cheer | 大合唱 | 全場塔攻速 +80%，持續 6 秒 |

威力隨稀有度與塔等級縮放，沿用既有的 `traitPower` / `LEVEL_POWER` 係數。

新增指令 `{ kind: "castUltimate"; characterId: string }`，模擬層驗證充能是否已滿。

### 操作

畫面底部固定一條**絕招列**：出戰隊伍的 5 個角色頭像，各自帶一圈充能環。充滿就發光並可以點，點下去該角色的所有塔一起放招。

位置固定、目標大、不用在地圖上找發光的塔——對小朋友最好懂。塔位面板（升級／賣出）改成開在絕招列之上。

## §4 戰鬥 HUD

- 蛋糕從「12/12」改成一排蛋糕圖示，被偷走就少一個——不用讀數字。
- 波次從「1/10」改成 10 個小圓點，打完一波填滿一顆。
- 暫停／速度／音量收成右上角一組小按鈕。
- 「開始第 N 波」移到畫面右下角（拇指範圍內），不再放在最上排。
- letterbox 的左右空白填上該關 `theme` 的漸層，並讓畫布圓角嵌進外框，不再看起來像沒畫完。

## 測試

- `slotPlanner.test.ts`：確定性（同輸入同輸出）、不壓路、不出畫面、間距、湊滿 count。
- `levels.test.ts`：改用新的「打得到路」與「涵蓋率」不變式，套用到全部 12 關。
- `simulation.test.ts`：充能累積、`castUltimate` 在未充滿時無效、8 種大招各自的效果、`ovenVent` 會扣血。
- 既有的模擬與波次測試維持全綠。

## 不做

- 不做格子地形（tile map）：要重寫 renderer 與 slot 系統，12 張圖全部重做。
- 不做多階段戰場／相機推進：規則對小朋友太難懂。
- 不做無盡模式或每日挑戰：使用者明確表示「太短」指的是路太短，不是內容太少。
